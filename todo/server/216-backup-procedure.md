# タスク 216: Cypher からバックアップを取るプロシージャ（db.backup）

## 背景（2026-11-23、task127 の残り）
task127（task148）で docs から外したプロシージャ。バックアップは今 CLI の `maharit backup`（`maharit-server/src/main.rs`、
`Backup::create` / `create_with_schema`）でだけ取れる。稼働中のサーバーに対して取る手段は無い。

※ 実装するかどうかは後で決める。決めるまでは着手しない。サーバーのファイルシステムに書き込むので、危険性も含めて判断する。

## 候補
- `CALL db.backup(path [, {compression: 'zstd'}]) YIELD path, bytes, nodes, relationships, durationMs` — admin のみ

## 課題
- 書き込み先の制限（任意のパスに書けると危険。設定で許可したディレクトリの下だけにする等）
- 一貫性: 書き込みを止めるか、スナップショットを取ってから書くか（WAL・チェックポイントとの関係）
- 長時間かかる処理をクエリのタイムアウト・接続の中でどう扱うか（非同期にしてジョブ ID を返す案も）
- サーバー側の状態に触るので、task215 のサーバー側プロシージャの仕組みが要る
- レプリケーション・シャーディング時にどのノードで取るか
