# 192: 書き込みのスループット（WAL の待ちとグループコミット）

## 問題

`CREATE` 1 件が 1 接続で 3 ms（330 件/秒）。エンジンは 2.66 µs なので、ほぼ WAL の fsync 待ち。8 接続でも 948 件/秒（2.9 倍）で、グループコミットが効ききっていない。
WAL のレコードは JSON、CRC32 は 1 ビットずつ計算する自前実装。

計測は task182 のベンチ（`bash scripts/run_bench_local.sh`、2026-11-16、10 コア）。

## 進め方

- 8 接続で伸びない理由を調べる（fsync 1 回に何件まとまっているか、`write_gate` を持つ時間）
- CRC をテーブル引きにする（依存を足さずにできる）。レコードのバイナリ化は形式の変更なので、旧形式の読み込みを残す
- macOS の fsync は遅いので、Linux でも測って判断する

## 完了の目安

- `PARALLEL CREATE x8` が x1 の 8 倍に近づく
- 変更の前後を `scripts/perf_check.py` で比べ、他の項目が遅くなっていないこと
