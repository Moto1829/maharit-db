# タスク 208: 数値・文字列リテラルの書き方を標準に合わせる

## 背景（2026-11-21、openCypher TCK）

```text
RETURN 0x1A2B, 0o17          // 16 進・8 進の整数（構文エラー）
RETURN .5, -.5               // 整数部の無い小数（構文エラー）
RETURN 1e9, 1.5E-3           // 指数表記（構文エラー）
RETURN -9223372036854775808  // 最小の整数（字句エラー：符号の前に 9223372036854775808 を読んで溢れる）
RETURN 'ǿ'              // Unicode のエスケープ（'u01FF' になる）
```

TCK: `literals/Literals2 [8]`、`Literals3`（16 進、11 シナリオ）、`Literals4`（8 進、8）、`Literals5`（小数・指数、21）、
`Literals6 [10] [13]`、`Literals7` `Literals8`（リスト・マップの中、9）。

## 作業
- [ ] 字句解析: `0x` / `0o` の整数、`.5`、指数（`e` / `E`、符号付き）
- [ ] `-9223372036854775808` を単項マイナスと組で読む（i64 の最小値）。それ以外の範囲外はエラー（`IntegerOverflow`）
- [ ] 文字列の `\uXXXX`（不正な値はエラー）。他のエスケープ（`\t` `\n` `\\` `\'` `\"`）が標準どおりか確認
- [ ] `feat(query):`（今まで構文エラーだったもの）。`\u` の意味が変わるので、その部分は `fix!` を検討
