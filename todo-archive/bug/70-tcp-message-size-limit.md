# bug/70: TCP メッセージ長プレフィックスの上限追加（メモリ枯渇 DoS 対策）

## 概要
`tcp_server.rs` の `read_message()` は先頭 4 バイトを `u32` のメッセージ長として読み取り、
上限チェックなしにバッファへ蓄積していた。悪意あるクライアントが最大約 4 GiB の長さを
宣言してデータを流し込むと、接続ごとに巨大なメモリを確保させられ DoS が成立する。

## 対応
- `MAX_MESSAGE_SIZE`（64 MiB）定数を追加。
- `read_message()` で宣言長が上限を超える場合、データ蓄積前に接続をエラー切断する。

## 影響
- 重大度: MEDIUM
- 正常系（64 MiB 以下のメッセージ）には影響なし。
