# タスク 154: コーディネーターのクエリの意味をシャーディングに合わせる

## 現状（2026-11-09 確認、bug/153 の作業中）
`maharit server --coordinator` は、受け取ったクエリを**そのまま全シャードに送り**、結果を連結して**同じ内容の行を 1 行にまとめて**返す。

- 書き込み（`CREATE` など）も全シャードに送られるため、同じデータが全シャードに作られる。`maharit-cluster` の Hash / Range 戦略（`router.rs`）はコーディネーターで使われていない
- 集計がシャードをまたいで合わない: `MATCH (n) RETURN count(n)` は各シャードの件数を返し、件数が同じなら重複除去で 1 行になる（2 シャードに 1 件ずつなら `1` が返る）
- 重複除去で、本来別の行（同じ値を持つ別ノード）も消える
- `ORDER BY` / `LIMIT` / `SKIP` はシャードごとに効き、全体では効かない
- シャードをまたぐパターン（エッジの両端が別シャード）は辿れない
- docs/advanced/sharding.md は `maharit-cluster` の Rust API（ルーティング）を説明しており、サーバーのコーディネーターの挙動とは一致しない

## 作業（案）
- [x] 書き込みのルーティング（作成するノードの ID / キーで 1 シャードを選ぶ）か、当面はコーディネーターでの書き込みを拒否するかを決める → 拒否（読み取り専用）。書き込みはシャードに直接
- [x] 読み取り: 集計（count / sum / min / max / collect）の合算、`ORDER BY` / `SKIP` / `LIMIT` / `DISTINCT` の全体適用、重複除去をやめる。avg など合算できないものはエラー
- [x] docs: コーディネーターの挙動と制限を sharding.md に明記
