# バグ 153: コーディネーターが数値などを返せず、シャードのエラーを空の結果にしていた

## 現象（2026-11-09 確認）
- `ShardClient` がシャードの `result` を `HashMap<String, String>` として読んでいたため、数値・真偽値・リスト・マップを含む行（`RETURN p.n`、`count(p)` など）がデシリアライズに失敗した
- コーディネーターはシャードのエラー（上記の失敗、構文エラー、シャードに接続できない）を `unwrap_or_default()` で空の結果に変えていたため、クライアントには `{"type":"result","rows":[]}` が返っていた
- 実機: 2 シャード構成で `MATCH (p:P) RETURN p.n` → 空、`MATCH (p:P RETURN p`（構文エラー）→ 空

## 対応
- [x] `RowValue::Json`（その他の JSON 値をテキストで保持）と `RowValue::from_json` / `to_json` を追加。`ShardClient` は JSON 値で読む
- [x] コーディネーターの応答の行を JSON 値のまま返す（数値は数値、リストはリスト）
- [x] どれかのシャードが失敗したらクエリ全体をエラーにする（`shard <id> (<addr>): <理由>`）
- [x] テスト: 実際の TcpServer 2 台に対する結合テスト（型、構文エラー、接続できないシャード）
- シャーディングの意味（書き込みの全シャード送信、集計、重複除去）は server/154 に起票
