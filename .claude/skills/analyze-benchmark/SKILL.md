# MaharitDB ベンチマーク分析

## 手順

### 1. 最新レポートを特定する

`benchmark_reports/` ディレクトリから最新の `.md` ファイルを Glob で取得し、ファイル名のタイムスタンプが最も新しいものを選ぶ。

### 2. レポートを読み込む

Read ツールでファイル全体を読み込む。

### 3. 結果テーブルを解析する

`## 計測結果` セクションの Markdown テーブルから各行を読み取り、以下の数値を把握する。
- 操作名 / 件数 / 時間(s) / スループット(/s) / レイテンシ(ms/op)

### 4. 分析を実施する

以下の4セクションで分析を行う。各セクションに `##` 見出しをつける。

**## パフォーマンス概評**
- 全体的な読み書きのバランス、突出して速い・遅い操作を具体的な数値とともに記述する。

**## ボトルネック分析**
- レイテンシが高い（> 5ms）操作を列挙し、それぞれの推定原因をアーキテクチャ観点（ロック競合、フルスキャン、N+1、シリアライズ等）で説明する。
- 同種クエリ間の性能差（例: 同じ WHERE フィルタでも条件によって差が大きい）に注目する。

**## 改善提案**
- 優先度順に3〜5件の具体的な改善策を示す。
  - インデックス追加、クエリプラン改善、バッチ書き込み、コネクションプール、並列化など
  - コードの場所や設計上のヒントがあれば添える（maharit-query/executor.rs 等）

**## 比較観点**
- 同規模データに対する Neo4j や ArangoDB 等の一般的な数値と比較し、MaharitDB の現状を評価する。
- Rust 実装の強みが活かせている箇所・活かしきれていない箇所を指摘する。

### 5. レポートに追記する

Edit ツールで対象ファイルの末尾にある `---` 区切りの直前に以下を挿入する。

```
---

## Claude による改善点分析

（生成した分析テキスト）
```

すでに `## Claude による改善点分析` セクションが存在する場合は、そのセクションの内容を新しい分析で置き換える。

### 6. 完了報告

分析を追記したファイルパスと、最も重要な改善提案1〜2件を簡潔に報告する。
