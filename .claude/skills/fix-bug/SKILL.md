# バグを直す

1. **再現テストを先に書き、落ちることを確かめる**。タスクに書かれた例をそのまま使う。
   クエリの意味の問題なら `crates/maharit-query/src/conformance_tests.rs` の `cases()`、エラーになるべきものは `executor/tests/` の該当ファイルに `assert!(execute(...).is_err())`
2. 原因を直す。同じ原因で起きる別の症状（タスクに挙がっていないもの）もテストに足す
3. 利用者から見える説明が変わるなら `docs/`（日本語と `.en.md`）も直す
4. `bash scripts/check.sh > check.log 2>&1 && tail -1 check.log` で `CHECK-OK` を確かめる（パイプで `tail` に渡して `&&` でつなぐと、失敗しても先へ進むので注意）
5. タスクを `git mv todo/bug/<file> todo-archive/` で移し、チェックボックスを埋め、末尾に「結果」として決めたこと（直さなかったこと、残した判断）を書く
6. 1 コミットで push する

## コミットの種類

- 普通は `fix(<クレート>): …`
- 同じクエリの結果が変わる・今まで通っていた入力がエラーになる修正は `fix(<クレート>)!: …` にして、本文に `BREAKING CHANGE:` を書く（CLAUDE.md の「後方互換を壊す変更」。迷ったら `!` を付ける）
- 本文は利用者に分かる言葉で書く（そのままリリースノートになる）。「これまで何が起きていたか」と「どうなったか」を書く
